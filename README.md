# Монитор разгона и разворота фьючерсов BingX

Новая версия читает публичные данные BingX без аккаунта и торговых ключей. Каждые пять минут она получает **все** USDT-тикеры, затем 5-минутные свечи **каждого** контракта с суточным диапазоном от 8%; VELVET и BAT проверяются отдельно даже в спокойный день. После первого запуска к проверке добавляются контракты с изменением цены от 1,2% между замерами, даже если суточный диапазон меньше 8%. Жёсткого лимита в 20 монет больше нет.

Две независимые ветки: 🔴 прежний памп и признаки разворота для ручного шорт-сценария; 🟢 ранний рост цены и объёма для наблюдения за разгоном. Во второй ветке рост открытого интереса рассчитывается **только между двумя реальными замерами** из публичного API. Без второго замера алерт остаётся наблюдением. Вход, стоп и цели — условные расчёты для самостоятельного решения, а не ордер или обещание результата. Сообщения Telegram содержат направление, статус, причины, уровни, время по Москве, оборот, спред и доступный контекст funding/дельты. Для подтверждённого сценария показываются расчётные TP1/TP2/TP3 на 1R/1,5R/2R; при наблюдении целей нет. Плечо сканер не назначает. Подробный аудит: [STRATEGY_AUDIT.md](STRATEGY_AUDIT.md).

Проверить локально без отправки сообщений:

```powershell
python -X utf8 run_monitor.py --dry-run
python -m unittest test_monitor.py
python -X utf8 backtest_monitor.py --symbols VELVET-USDT BAT-USDT
python -X utf8 backtest_momentum.py --sample 60
```

Для постоянной работы подготовлен `.github/workflows/five-minute.yml`: запуск по UTC в 02, 07, 12… минуты каждого часа, а также вручную. Код предназначен для **отдельного публичного** репозитория GitHub, выбранного пользователем; старый закрытый репозиторий не меняется. Нужны разрешённые Actions и секреты `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Токен бота никогда не помещай в код. Workflow создаёт ветку `scanner-state` с несекретными снимками цен и открытого интереса, историей и отметками отправленных сигналов; ему нужен `contents: write`. Первый ручной запуск и следующее расписание нужно проверить в **Actions**, а тестовую доставку — в Telegram. До такой проверки монитор нельзя считать запущенным.

GitHub [допускает 5-минутное расписание](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule), но не гарантирует точное время и может пропустить запуск. Для VELVET и других монет обнаружение разворота остаётся статистической гипотезой: предварительный исторический тест не подтвердил стабильного падения на 20–30% после сигнала. Сканер не торгует.

Старая версия Google Apps Script остаётся в прежнем закрытом проекте. Если её триггеры всё ещё активны, после проверки GitHub-монитора их нужно отключить, чтобы не получать дубли. Новый публичный репозиторий содержит только код нового монитора без токена бота.
